# 批量重命名

TOS 7 的批量重命名工具。在当前用户有权访问的个人目录和共享目录中，预览文件名变化、检查冲突、确认执行，并撤销已成功的项目。

## 安装与使用

从 [GitHub Releases](https://github.com/LuYifei2011/tos-batch-rename-tool/releases) 下载对应架构的 deb 包：

| 设备架构 | 安装包 |
| --- | --- |
| x86_64 | `batch-rename_0.1.0_amd64.deb` |
| aarch64 | `batch-rename_0.1.0_arm64.deb` |

在 TOS 应用中心手动安装，使用浏览器登录 TOS，再从桌面打开“批量重命名”。应用通过当前 TOS 会话发现目录，无需配置 NAS 地址或额外账号。非管理员需由 TOS 管理员授予应用访问权限，文件访问仍由当前用户的权限决定。

1. 在右侧共享文件夹列表中打开目录。
2. 在左侧添加查找替换、命名编号、前后缀、大小写、空白清理或扩展名规则。
3. 检查原名、新名和冲突提示，确认选择范围后执行。
4. 在任务结果中查看状态，或撤销当前目录中已确认成功的项目。

规则按顺序应用。筛选只改变显示范围，保留原有选择和编号顺序。预览使用独立 Web Worker，表格只渲染可视区域。

## 语言与主题

左下角“语言与主题”提供独立设置：

- 语言：跟随 TOS、跟随浏览器、简体中文、English。
- 主题：跟随 TOS、跟随浏览器、浅色、深色。

首次使用默认跟随 TOS。TOS 偏好不可用时回退到浏览器设置；手动选择优先。切换即时生效，保留规则、选择和预览，设置保存在当前浏览器。存储不可用时仍可在本次页面内使用。

跟随 TOS 语言读取同源 `/v2/timesetting/getlang` 的 `data.tos_lang`；中文显示为简体中文，其他有效语言显示为英文。跟随 TOS 主题优先读取 `themeMode` Cookie，缺失时请求 `/v2/person/desktopDisplay` 的 `data.display_mode`。请求沿用当前会话，失败或超过 2 秒时回退。页面恢复可见、获得焦点及可见时每 30 秒同步；跟随浏览器模式不请求 TOS 偏好接口。

## 文件操作边界

- 只处理当前目录，不递归。单目录最多 100,000 项，单批最多 50,000 项，默认四路并发，全服务同时运行一批。
- 仅提供内部存储卷上的个人目录和共享目录，过滤卷根、homes 集合、`@apps` 等系统目录。回收站和平台标记为符号链接的条目不参与改名。
- 已有目标、大小写改名、名称交换及循环依赖会提示冲突；前端还检查 NFC 等价名称。
- 计划绑定当前会话，5 分钟过期，仅能执行一次。确认执行时重新扫描 TOS 目录，每项提交前再次读取源属性。
- TOS 文件服务没有已确认的比较后原子改名接口，目标冲突处理依赖 `folderRename`。本地演示模式的原子不覆盖保证不能外推到 TOS。执行期间应避免其他应用同时修改目录。
- TOS 源标识由类型、大小、秒级修改时间和所有者组成，无法识别属性完全相同的文件替换。本地标识还包含设备和 inode；两者均非内容哈希，不读取或复制文件内容。
- 停止影响尚未开始的项目，已提交的操作仍会返回结果。会话失效或平台拒绝操作时停止后续提交，单批可能部分完成。
- 提交前同步 intent 日志，再记录结果。写请求断线、超时或响应无法判定时标记为“需核对”，不自动重试。异常退出后也不自动执行或撤销。
- 撤销仅恢复已确认成功、源属性仍匹配且原名空闲的项目。目录移动、会话更换或属性变化后，需按实际文件状态核对。
- 保留最近 32 批记录，创建任务时轮转最早的已结束记录及撤销信息。状态不确定的中断记录保留；此类记录达到 32 批时暂停新任务。

## 认证、服务与数据

前端通过同源 `/v2/proxy/batch-rename/api/...` 访问后端。TOS 网关处理应用访问授权；后端验证会话、CSRF 和请求来源，将当前凭据转交固定的本机 TOS 文件服务 `127.0.0.1:8181` 校验并执行文件操作。应用账号不直接读取用户文件，不修改共享目录 ACL，平台调用不跟随重定向。

会话失效时清空应用视图并前往 TOS 登录页；应用访问被拒绝时停止请求并显示诊断。目录写入被平台拒绝时显示操作错误。启动 GET 遇到 502/503/504 时最多重试三次，写请求不自动重试。

连接诊断仅保留版本、响应格式、状态码和凭据是否可读等信息，不记录 Cookie、令牌、查询参数值或响应原文。诊断保留在当前页面内存，可选中复制。

业务服务以非 root 的 `batch-rename` 账号运行，使用 systemd Unix socket `/var/api/batch-rename.sock`，权限为 `0660`，不开放应用 TCP 端口。服务启用时由 systemd 以 root 执行一次固定路径的数据目录权限初始化，随后以应用账号启动业务进程。初始化仅调整数据目录本身，不递归修改文件；账号缺失时停止启动并记录错误。安装时若账号尚未创建，完成服务注册后需在账号可用时通过 TOS 启用应用。

运行数据位于 `/usr/local/batch-rename/data/`，升级与卸载保留记录：

| 路径 | 用途 |
| --- | --- |
| `history/<id>.json` | 任务快照，仅保存会话哈希 |
| `history/<id>.json.part` | 正在同步的快照 |
| `history/<id>.jsonl` | 每项提交意图与结果，单批最多 100,000 条 |

会话凭据仅存于请求和运行任务的内存中。记录按会话哈希隔离，新登录会话无法查看或撤销旧会话的记录；管理员可按记录核对文件状态。

## 开发与发布

需要 Node.js 24、`.go-version` 指定的 Go 1.27.4、Python 3。安装包运行时无需 Node.js 或互联网连接。

```sh
npm ci
npm run build
sh scripts/dev.sh
```

打开 `http://127.0.0.1:18946` 使用隔离的本地演示目录。演示文件是文本测试数据，图片后缀仅用于名称预览。构建、测试及标签发布方式见[开发与发布指南](docs/DEVELOPMENT.md)，当前版本内容见[发布说明](docs/RELEASE_NOTES.md)。
